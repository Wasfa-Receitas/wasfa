# 🍲 Wasfa

Wasfa is a Portuguese-language recipe discovery website where users can browse recipes by category, save favorites, and manage a personal profile. It's built as a static front-end project (HTML, CSS, TypeScript) with a lightweight client-side authentication flow using `localStorage`.

> **Wasfa** means "recipe" in Arabic — reflecting the app's focus on helping people find the perfect dish for their craving.

---

## 📖 Description

Wasfa lets users:

- Browse a homepage with a rotating "food wheel" that cycles through meal categories (Lunch & Dinner, Dessert, Refreshments, Snacks).
- Search and filter recipes by category (Lunch, Dessert, Refreshment, Snack, Spicy, Vegetarian).
- Create an account and log in (client-side, no backend required).
- View a personal profile page with quick access to favorites, saved recipes, and menus.
- Enjoy a fully responsive layout with a mobile navigation menu.

The project is intentionally framework-free on the front end — plain HTML/CSS with TypeScript compiled to vanilla JavaScript — making it easy to read, extend, and deploy anywhere.

---

## ✨ Features

- 🎡 **Animated category wheel** on the homepage that rotates and updates the page title automatically.
- 🔍 **Recipe search bar** for quickly finding dishes.
- 🏷️ **Category filters** (Lunch, Dessert, Refreshment, Snack, Spicy, Vegetarian) with distinct color-coded styles.
- ❤️ **Favorite button** on each recipe card (toggles between outline and filled heart icon).
- 🔐 **Sign up / Log in / Log out** flow using `localStorage` (no backend needed for the demo).
- 👤 **Profile page** with shortcuts to favorites, personal recipes, and a menu section.
- 📱 **Fully responsive design**, including a dedicated mobile navigation drawer.
- 🧑‍💻 **TypeScript support** for safer, more maintainable client-side scripts.

## ⚙️ Installation

### Prerequisites

- [Node.js](https://nodejs.org/) (v16 or later recommended)
- npm (comes bundled with Node.js)
- A modern web browser
- (Optional) A local static server, e.g. [Live Server](https://marketplace.visualstudio.com/items?itemName=ritwickdey.LiveServer) for VS Code

### Steps

1. **Clone the repository**
   ```bash
   git clone https://github.com/Wasfa-Receitas/wasfa.git
   cd wasfa
   ```

2. **Install dependencies**
   ```bash
   npm install
   ```

3. **Compile the TypeScript source**
   ```bash
   npm run build
   ```
   This compiles the files in `src/ts/` into plain JavaScript inside `js/dist/`.

4. **Open the project**
   - Simplest: open `index.html` directly in your browser.
   - Recommended: serve it with a local static server (avoids issues with relative paths and browser caching):
     ```bash
     npx serve .
     ```

## 🚀 Usage

- **Browsing recipes:** Go to `pages/receitas.html` and use the category buttons to filter, or the search bar on the homepage.
- **Creating an account:** Navigate to `pages/login.html`, switch to the "Criar Conta" tab, and fill in your details. Accounts are stored in `localStorage` under the provided email.
- **Logging in:** Use the same page's "Entrar" tab with your registered email and password. On success, you're redirected to `pages/perfil.html`.
- **Logging out:** Click the logout button, which clears the `loggedUser` key from `localStorage`.
- **Favoriting a recipe:** Click the heart icon on any recipe card to toggle it as a favorite.

### Development workflow

While editing TypeScript files, run the watch mode to auto-recompile on save:

```bash
npm run watch
```

## 🤝 Contribution Guidelines

Contributions are welcome! To keep things consistent, please follow these guidelines:

1. **Fork** the repository and create your branch from `main`:
   ```bash
   git checkout -b feature/your-feature-name
   ```
2. **Write TypeScript**, not plain JavaScript, for any new client-side logic. Keep files under `src/ts/` and let `tsc` generate the output in `js/dist/`.
3. **Follow existing naming conventions**: Portuguese for user-facing content and file names already in Portuguese (e.g. `receitas.html`, `sobre.html`), English for code identifiers where practical.
4. **Keep styles consistent** with the existing design tokens defined in `:root` (`--purple-main`, `--orange`, `--yellow`, etc.) in `style.css`.
5. **Test responsiveness** at common breakpoints (mobile, tablet, desktop) before submitting.
6. **Write clear commit messages**, e.g.:
   ```
   feat: add recipe rating filter
   fix: correct broken stylesheet link in perfil.html
   docs: update README installation steps
   ```
7. **Open a Pull Request** against `main`, describing:
   - What the change does
   - Why it's needed
   - Screenshots/GIFs for any UI changes
8. Be respectful and constructive in code reviews — this is a learning project built by a small team, and clear feedback helps everyone improve.

### Reporting Issues

If you find a bug or have a feature request, please open an issue including:
- Steps to reproduce (for bugs)
- Expected vs. actual behavior
- Browser/OS information, if relevant
